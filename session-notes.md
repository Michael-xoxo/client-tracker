## Task 2.1 - User Entity, Password Hashing & JWT Authentication Guard (2026-11-02)
- **Architectural Decision**: Used an async Mongoose `pre('save')` middleware hook without the legacy `next` callback parameter to align with Mongoose 9's promise-based middleware architecture, ensuring passwords are only hashed when modified (`this.isModified('password')`) and never returned in JSON payloads or `req.user` queries (`select('-password')`).
- **Friction Point / Bug Encountered**: During adversarial verification via `curl.exe` in Windows PowerShell, inline double quotes in `-d` arguments were stripped by PowerShell's native command argument parser, causing `body-parser` JSON `SyntaxError`s and connection race conditions before MongoDB finished connecting. Resolved by polling port 5000 readiness with `Test-NetConnection` and piping the JSON payload via stdin (`-d "@-"`) to `curl.exe`.

## Task 2.2 - Relational Project & Embedded Milestone API (2026-11-02)
- **Architectural Decision**: Enforced tenant isolation directly inside Mongoose queries (`{ _id: req.params.id, user: req.user._id }`) combined with `mongoose.Types.ObjectId.isValid` pre-checks and positional `$set` updates (`'milestones.$.completed'`) to guarantee atomic sub-document mutations while returning uniform `404` responses on unauthorized or malformed IDs (preventing cross-user enumeration and unhandled `CastError`s).
- **Friction Point / Bug Encountered**: Mongoose 9 deprecated the `{ new: true }` option on `findOneAndUpdate()`, emitting a runtime deprecation warning during `PATCH /api/projects/:id/milestones/:milestoneId`; updated the query options to `{ returnDocument: 'after', runValidators: true }`.


## Task 2.3 - Client Scaffold, AuthContext & Session Management (2026-11-03)
- **Architectural Decision**: Structured `AuthContext` with lazy `useState` initializers that hydrate `token` and `user` directly from `localStorage` on initial render (eliminating an unauthenticated flash on page reload) while verifying active sessions against `GET /api/auth/me` via the Vite `/api` proxy and automatically purging `localStorage` on `401` responses.
- **Friction Point / Bug Encountered**: Vite 8's bundled `oxlint` flagged `react(set-state-in-effect)` when resetting session verification state synchronously at the top of `useEffect` in `App.jsx`; resolved by keying the verification state object by `token` and deriving the `verifying` status during render until the async `/api/auth/me` promise resolves.

## Task 2.4 - Contractor Project Dashboard & Milestone Task Board (2026-11-03)
- **Architectural Decision**: Maintained a single normalized `projects` array in `ProjectDashboard` state and derived both `selectedProject` and `progressPercentage` via `useMemo`, ensuring that `POST` and `PATCH` responses from `/api/projects/:id/milestones` atomically replace the matching project object in state and immediately recalculate completion percentages without redundant refetches.
- **Friction Point / Bug Encountered**: Deleting the currently active project could leave `selectedProjectId` pointing to a removed entity if not reconciled during state updates; resolved by computing the remaining project list inside the `setProjects` updater and clearing or advancing `selectedProjectId` so the Milestone Task Board unmounts cleanly when the last project is deleted.

## Task 2.5 - Public Client Portal View & Production Hardening (2026-11-03)
- **Architectural Decision**: Mounted `GET /api/projects/portal/:id` in `routes/projectRoutes.js` prior to the router-level `router.use(protect)` middleware and explicitly projected only `{ _id, title, clientName, status, milestones }` in `getPublicProjectPortal`, guaranteeing zero leakage of owner `user` ObjectIds, `clientEmail`, or `budget` fields to unauthenticated portal viewers.
- **Friction Point / Bug Encountered**: Express 5 uses `path-to-regexp` v8, which rejects legacy bare `*` catch-all routes with a `PathError`; used the named splat parameter syntax `app.get('/{*splat}', ...)` in `server.js` to serve `client/dist/index.html` cleanly in production mode.
